# Requirements: Fix Dev Google Indexing

## Summary

The `dev.fromthehart.tech` site is being crawled and flagged by Google as "Duplicate without user-selected canonical" because the build is zero-environment-aware. Both `robots.txt` (generated by `@nuxtjs/sitemap`) and `<meta name="robots">` (hardcoded in `app.vue`) allow indexing on all environments. Additionally, `site.url` is hardcoded to `https://www.fromthehart.tech`, so the sitemap module generates identical `robots.txt` and `sitemap.xml` for both dev and prod.

Install `@nuxtjs/robots` and wire `NUXT_SITE_ENV` in CI to make the build environment-aware. The robots module auto-blocks indexing on non-production environments, generates correct per-env `robots.txt`, injects `<meta name="robots">` tags, and integrates with `@nuxtjs/sitemap` to exclude non-indexable pages.

## User Stories

- **As a site owner**, I want `dev.fromthehart.tech` to be completely invisible to search engines, so that Google never flags it as duplicate content and never serves dev pages in search results.
- **As a site owner**, I want `www.fromthehart.tech` search indexing to work correctly, with proper `robots.txt`, sitemap, and meta tags.
- **As a site visitor**, I want Google search results to never show dev URLs (`dev.fromthehart.tech`), only production URLs (`www.fromthehart.tech`).

## Acceptance Criteria

### AC-1: Dev site blocks all search engine indexing
**Given** the dev site is deployed at `dev.fromthehart.tech`  
**When** a search engine crawler requests `robots.txt`  
**Then** it receives `User-agent: *` / `Disallow: /` (blocks all crawling)  
**And** every HTML page includes `<meta name="robots" content="noindex, nofollow">`

> **Note:** `X-Robots-Tag` HTTP header is not achievable on static S3 hosting (no server to set response headers). The `robots.txt` + `<meta>` tag combination is sufficient for Google to stop indexing.

### AC-2: Prod site allows indexing
**Given** the prod site is deployed at `www.fromthehart.tech`  
**When** a search engine crawler requests `robots.txt`  
**Then** it receives `User-agent: *` / `Disallow:` (allows all crawling) with a link to the prod sitemap  
**And** every indexable HTML page includes `<meta name="robots" content="index, follow">`

> **Note:** `X-Robots-Tag` HTTP header is not achievable on static S3 hosting (see AC-1 note).

### AC-3: Dev has no usable sitemap (blocked by robots.txt)
**Given** the dev site is deployed at `dev.fromthehart.tech`  
**When** a crawler requests `robots.txt`  
**Then** it receives `Disallow: /` with no sitemap reference (or an irrelevant/empty sitemap — the key is that `robots.txt` blocks all crawling first)

**Given** the prod site is deployed at `www.fromthehart.tech`  
**When** the sitemap is generated  
**Then** all `<loc>` URLs point to `https://www.fromthehart.tech/...`  
**And** pages marked non-indexable by the robots module are excluded from the sitemap

### AC-4: Pages behind login excluded from sitemap and indexing (prod)
**Given** the prod site is deployed  
**When** Google crawls the sitemap  
**Then** pages behind authentication are NOT present in the sitemap and are marked `noindex`  
**And** this is achieved via route rule glob patterns in `nuxt.config.ts` (not per-page manual changes)

Specifically excluded by default: `/auth/email-verification-required`, `/auth/verify-email` (post-login flow pages), `/user/**` (profile pages), `/storage/**` (WIP pages behind login).

**And** adding a future exclusion is a one-line route rule addition.

### AC-5: Build is environment-aware via NUXT_SITE_ENV
**Given** the CI pipeline for dev or prod  
**When** `npm run generate` executes  
**Then** the dev workflow sets `NUXT_SITE_ENV=dev` and the prod workflow does NOT set it (module defaults to `production` → indexing enabled)  
**And** the generated static output differs between dev and prod (different `robots.txt`, different meta tags)  
**And** local dev (`npm run dev`) uses `.env` with `NUXT_SITE_ENV=dev`  
**And** `nuxt.config.ts` has a fallback for safety: if `NUXT_SITE_ENV` is not set, it defaults to `'dev'` (safe default — only CI prod overrides to enable indexing)

### AC-6: Google Console error is actively resolved
**Given** the fix is deployed to `dev.fromthehart.tech` and verified serving `noindex`  
**When** a Google Search Console **Removal Request** is submitted for `dev.fromthehart.tech/*`  
**Then** the "Duplicate without user-selected canonical" error for `dev.fromthehart.tech/` no longer appears in the Coverage report  
**And** dev pages are removed from Google's index  

> **Note:** Passive waiting for Google to re-crawl is slow (weeks). Submitting a manual removal request via GSC is the recommended path. The `dev.fromthehart.tech` GSC property may become inactive after all URLs are removed — this is expected and acceptable.

## Constraints

- **C1:** No OG/twitter changes to `app.vue` — OG/twitter URLs stay hardcoded to prod (all public links must point to production). The hardcoded `robots` meta line WILL be removed from `app.vue`'s `useSeoMeta` to avoid conflicting with `@nuxtjs/robots` module injection.
- **C2:** Must use `@nuxtjs/robots` module (chosen solution). No custom `robots.txt` files in `public/`, no post-build CI overrides.
- **C3:** Must remain a fully static SPA (`npm run generate`) — the robots module's `zeroRuntime`-compatible mode must work.
- **C4:** `@nuxtjs/sitemap` must remain at v8 (`zeroRuntime: true`). The robots module must integrate cleanly with it.
- **C5:** `NUXT_SITE_ENV` is the only new env var. Dev CI sets `NUXT_SITE_ENV=dev`. The `@nuxtjs/robots` module treats any value except the literal `'production'` as non-production (indexing disabled). Prod CI does NOT set it (module defaults to `production` → indexing enabled). For safety, `nuxt.config.ts` falls back to `'dev'` if the env var is unset, so a local build without `.env` defaults to safe (blocking) behavior.

## Non-Goals

- Fixing OG/twitter image URLs (they intentionally point to prod — C1)
- Adding `@nuxtjs/robots` configuration beyond the defaults (no custom `groups`, no `blockAiBots`, no custom `allow`/`disallow` — only route rules for behind-login pages)
- Changing individual page `<script setup>` code beyond removing the `robots` line from `useSeoMeta` calls. All other meta fields (title, description, OG, etc.) stay as-is.
- Removing all hardcoded `robots` meta lines from page files — this IS in scope (see C1 and design.md §Data Model). The only exception is `pages/blog/[...slug].vue` which keeps `post?.robots` (content-driven, per-blog-post configurable via Nuxt Content frontmatter). The `types/blog.ts` type definition is also preserved.
- Fixing the stale prod sitemap (last generated Oct 2025 — will be fixed on next prod deploy)
- Making `/auth/forgot-password` and `/auth/reset-password` non-indexable — these are public pages and should remain indexable
